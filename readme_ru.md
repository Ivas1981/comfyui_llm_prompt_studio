# ComfyUI LLM Prompt Studio

Пакет пользовательских узлов (custom nodes) для ComfyUI, который управляет
**адаптивным к архитектуре промпт-инжинирингом** с помощью **локальной LLM**, работающей
через [LM Studio](https://lmstudio.ai) или любой **локальный сервер совместимый с OpenAI**.
Он подстраивает вывод под загруженную базовую модель — SDXL, SD1.5, Pony, Illustrious,
Flux и SD3, — а не только под SDXL.

Он замыкает весь цикл: **сгенерировать промпт → отрисовать изображение → оценить его
зрительной моделью → автоматически переработать → сохранить одобренные результаты
с полными метаданными**, а также включает библиотеку промптов, пересборку сцен из
изображений и умную загрузку моделей/LoRA.

Никакого облака, никаких API-ключей не требуется — всё работает на вашем компьютере.

## Назначение (Intended Usage)

Пакет рассчитан на **однопользовательскую, одномашинную и одноэкземплярную** работу с ComfyUI:

- **Один пользователь на машину** — пакет загружает/выгружает LLM-модель на вашем локальном
  сервере LM Studio и подстраивает промпты под *вашу* загруженную модель. Он не предназначен
  для многопользовательского или хостингового использования.
- **Один экземпляр ComfyUI** — узлы используют один сервер LM Studio и считают, что загруженная
  модель принадлежит им; запуск нескольких ComfyUI на одном сервере может привести к гонкам
  загрузки/выгрузки модели.
- **Один конвейер за раз** — запускайте одну цепочку генерации/оценки промптов за сессию, чтобы
  цикл авто-доработки и освобождение VRAM работали предсказуемо.
- **Локальная LLM в LM Studio** (или любой локальный сервер совместимый с OpenAI) с загруженной
  моделью до запуска узлов.

## Возможности

- **Prompt Writer (Писатель промптов)** — превращает свободную идею (на любом языке) в точный
  SDXL-промпт, с опциональными промптами для дорисовки лица.
- **Image Critic (Критик изображений)** — зрительная модель оценивает отрисованное изображение
  по промпту и возвращает конкретные замечания для переработки.
- **Цикл авто-переработки** — при включении замечания критика подаются обратно в Писатель,
  и рабочий процесс автоматически ставится в очередь заново, пока не будет одобрен или не
  достигнут `max_retries`.
- **Smart Save (Умное сохранение)** — сохраняет только одобренные изображения как JPEG с промптами,
  моделью, LoRA и параметрами сэмплера, записанными в EXIF.
- **Библиотека промптов** — переиспользуемые сцены, хранящиеся в JSON-файле; сохраняйте и
  перезагружайте их.
- **Scene Builder (Конструктор сцен)** — двухэтапный: описывает изображение зрительной моделью,
  затем составляет новый промпт из этого описания (+ ваши правки).
- **Smart Loader (Умная загрузка)** — загружает чекпоинт, автоматически определяет его
  дистиллированное семейство (DMD / LCM / Turbo / Hyper / Lightning / Flash, а также `schnell`/`tcd`/`pcm`,
  сопоставленные с базовыми семействами) и условно применяет дистиллированную LoRA. Он выдаёт
  `detected_family` (**эффективное** семейство — применённая к базовому чекпоинту дистиллированная
  LoRA включается в него, поэтому режим без негатива автоматически включается далее по цепочке)
  и `detected_family_info` с источником обнаружения (`filename` / `metadata` / `base` / `override`).
  Виджет показывает **собственное** семейство чекпоинта и уведомление, когда была применена
  дистиллированная LoRA, напр.
   `family: base | source: filename | LoRA applied: dmd_lora.safetensors (distilled: dmd)`.
   Он также сообщает базовую **`architecture`** (SDXL / SD1.5 / Pony / Illustrious / Flux / SD3)
   через `detected_architecture` / `detected_architecture_info`; подключите `detected_architecture`
   к входу `architecture` Писателя / Конструктора сцен, чтобы адаптировать стиль токенов и негативы
   под базовую модель (генерация SDXL не меняется, когда вход пуст).
- **Индикатор статуса сервера LM Studio** — Писатель / Критик изображений / Конструктор сцен
  показывают живой виджет `server_status` (`● Подключено — <имена загруженных моделей>` /
  `● Подключено (модель не загружена)` / `● Сервер недоступен`), опрашиваемый с маршрута статуса
  пакета каждые несколько секунд.
- **Smart Multi-Clip** — кодирует до четырёх пар промптов одним CLIP с общими настройками размера,
  с учётом архитектуры: подключите `detected_architecture` от Smart Loader для не-SDXL моделей.
- **Стилевые пресеты** — выбор из ~50 встроенных стилей, сгруппированных по категориям
   (Фотография, Художественные течения, Азиатское искусство, Традиционные медиа, Цифровое и
   современное, Фэнтези и хоррор, Эпохи и стили, Базовые стили); в комбобоксе показываются
   метки `Категория > Название`. Пресет добавляет свои стилевые теги к промпту и может
   переопределить системный промпт. У Писателя / Конструктора сцен также есть вход `architecture`,
   адаптирующий стиль токенов и негативы по умолчанию для SD1.5 / Pony / Illustrious / Flux / SD3.
- **Расширенные опции LM Studio v1** — `reasoning`, `flash_attention`, `offload_kv_cache_to_gpu`,
  `repeat_penalty`, `top_k`, `top_p`, `min_p` передаются в нативный v1 API LM Studio, когда поддерживается.
- **Профиль загрузки модели** — комбобокс `load_model_profile` (Писатель / Критик / Конструктор сцен)
  применяет рекомендованный профиль сэмплирования (`auto` выбирает его из универсальной эвристики
  по размеру модели, без жёстко заданного списка моделей). Регулировки загрузки модели
  (`context_length`, `gpu_offload`, `flash_attention`, `offload_kv_cache_to_gpu`) скрыты за кнопкой
  **«⚙ Расширенные настройки»** (рядом с `load_model_profile`) и свёрнуты по умолчанию; нажмите её,
  чтобы показать/скрыть их.
- **Отладочное логирование** — опционально (`debug.py`, ВЫКЛ по умолчанию) логирует активность
  узлов/HTTP/парсинга с маскировкой API-ключей и бинарных образов.

## Критические изменения в 1.1.0

- **Удалена живая потоковая передача (live streaming).** Виджеты `stream` / `generation_view`,
  потребитель SSE (`_consume_sse`), колбэк `on_delta`, путь websocket-моста, переменная окружения
  `STREAM_WATCHDOG_SEC` и `test_stream_ws_push.py` удалены. Генерация теперь возвращает полный
  промпт/описание один раз — по завершении; живого побуквенного отображения больше нет.
- **`load_model_profile` теперь всегда присутствует** (по умолчанию `auto`) в Писателе / Критике
  изображений / Конструкторе сцен. Рабочие процессы, сохранённые до появления этого виджета,
  загрузятся с применённым рекомендованным профилем `auto`, пока вы не выберете `custom`.
- **Системные/стилевые промпты теперь живут только в `presets_default.json`.** Редактируемый файл
  `prompts.json` удалён; базовые промпты читаются из `presets_default.json` через `nodes/_defaults.py`.

## Требования

- ComfyUI — **рекомендуется и протестировано на ComfyUI 0.19.3 (классическая)**.
- Python-пакеты: `requests`, `numpy`, `pillow` (объявлены в `requirements.txt`;
  обычно уже присутствуют в окружении ComfyUI).
- **LM Studio** с запущенным локальным сервером (по умолчанию `http://localhost:1234/v1`).
  - Чат/instruct-модель для текстовых задач Писателя / Критика.
  - Модель с **поддержкой зрения** (Qwen2.5-VL, LLaVA, Gemma-3, …) для анализа изображений
    Критиком и Конструктором сцен.
- Режим рассуждения (thinking), если ваша модель его поддерживает, следует **отключить в LM Studio**.
  Примечание: когда модель возвращает пустой `content`, но непустой `reasoning_content`
  (режим thinking), пакет откатывается к использованию этого текста рассуждения как промпта
  (см. `lm_http.chat_completion`). Чтобы рассуждения не попадали в промпты и критику, отключите
  thinking для этой модели в LM Studio.

## Установка

1. Склонируйте / скопируйте эту папку в `ComfyUI/custom_nodes/`:
   ```
   ComfyUI/custom_nodes/comfyui_llm_prompt_studio/
   ```
2. Установите зависимости (если отсутствуют):
   ```
   pip install requests numpy pillow
   ```
3. Запустите LM Studio, загрузите модель и включите локальный сервер.
4. Перезапустите ComfyUI. В консоли должно появиться:
   ```
    [LLMPromptStudio] Package loaded: LLMPromptStudioWriter, LLMPromptStudioCritic,
    LLMPromptStudioSmartSave, LLMPromptStudioLibraryLoader, LLMPromptStudioSceneBuilder,
    LLMPromptStudioSmartLoader, LLMPromptStudioMultiClipSDXL, LLMPromptStudioSmartParameters,
    LLMPromptStudioKSamplerHiresFix, LLMPromptStudioFaceDetailer.
    ```

## Узлы

Все узлы находятся в категории **`LLM Prompt Studio`**.

### LLM Prompt Studio Writer (Писатель)

Генерирует SDXL-промпт из идеи.
  - **Входы:** `server_url`, `api_key`, `model`, `load_model_profile`, `context_length`, `gpu_offload`,
    `system_prompt`, `idea`, `revision_notes`, `temperature`, `max_tokens`, `seed`,
    `reuse_last_prompt`, `generate_face_prompts`, `max_field_retries`,
    `face_prompt_instruction`, `prompt_mode`, `family`, `architecture`, `style_preset`,
    `reasoning`, `flash_attention`, `offload_kv_cache_to_gpu`, `repeat_penalty`,
    `top_k`, `top_p`, `min_p`, `server_status`, `release_vram_after_run`.
  - **`prompt_mode`** выбирает, как обрабатывается негативный промпт: `auto` (по умолчанию)
    переключается на системный промпт без негатива, когда семейство чекпоинта дистиллировано
    (DMD / LCM / Turbo / Hyper / Lightning / Flash, **либо** применена дистиллированная LoRA к
    базовому чекпоинту — Smart Loader включает семейство LoRA в `detected_family`); `standard`
    всегда выдаёт негатив; `no_negative` всегда выдаёт пустой негатив. Дистиллированные модели
    сэмплируются при CFG ~1, где негативный промпт математически игнорируется, поэтому промпт
    без негатива перефразирует каждое ограничение как утвердительное.
  - **`load_model_profile`** (всегда виден, сразу под `model`): выбирает рекомендованный
    **профиль сэмплирования + загрузки** для выбранной модели. `auto` (по умолчанию) применяет
    профиль, выбранный *универсальной* эвристикой — размер модели считывается из её id
    (`qwen2.5-14b-instruct` → 14B, `nvidia/nemotron-3-nano-4b` → 4B) и сопоставляется с профилем
    **без жёстко заданного списка моделей**: модели ≥7B получают `baseline` + структурированный
    JSON-вывод, <7B получают `strict`, а нераспознанные размеры откатываются к безопасному `baseline`.
    Остальные варианты выбирают фиксированный профиль (`baseline` / `structured` / `creative` /
    `strict`), а `custom` сохраняет ваши индивидуально заданные виджеты сэмплирования
    (полная обратная совместимость со старыми рабочими процессами). Когда профиль активен, его
    параметры сэмплирования (temperature / top_p / top_k / repeat_penalty / presence_penalty /
    min_p / reasoning) **переопределяют** индивидуальные виджеты сэмплирования, которые затем
    игнорируются (это логируется). Структурированный вывод (JSON-схема `response_format`)
    используется только для текстового вывода `writer` / `compose` и **никогда** с изображением
    (вводом зрения) или этапом `describe`.
  - **`Advanced settings` (Расширенные настройки)** (кнопка): `context_length`, `gpu_offload`,
    `flash_attention`, `offload_kv_cache_to_gpu` **и виджеты сэмплирования** `temperature`,
    `max_tokens`, `repeat_penalty`, `top_k`, `top_p`, `min_p` скрыты за кнопкой
    **«⚙ Расширенные настройки»** (рядом с `load_model_profile`) и свёрнуты по умолчанию. Нажмите
    кнопку, чтобы показать/скрыть их (значения виджетов сохраняются, поэтому узел всегда получает
    параметры).
   - **`family`** (опционально) — подключите сюда выход `detected_family` Smart Loader, чтобы `auto`
    автоматически определял дистиллированное семейство. Поскольку Smart Loader включает применённую
    дистиллигентную LoRA в `detected_family`, базовый чекпоинт с LoRA DMD/LCM/Turbo/… также
    включает режим без негатива. Оставьте неподключённым, чтобы использовать `standard`.
   - **`architecture`** (опционально) — подключите выход `detected_architecture` Smart Loader
    (или задайте значение вручную), чтобы адаптировать сгенерированный промпт к базовой архитектуре:
    переключает стиль токенов и добавляет архитектурно-специфичные негативы по умолчанию для
    `Flux` / `SD3` / `SD1.5` / `Pony` / `Illustrious` (SDXL не меняется, когда пусто/не подключено).
    `Flux` и `SD3` также принудительно включают режим без негатива независимо от `prompt_mode`.
  - Загружает выбранную модель на сервере LM Studio **по требованию** (через API загрузки) с
    `context_length` (по умолчанию 8192), `gpu_offload` (1.0 = максимум GPU) и расширенными
    опциями загрузки (`flash_attention`, `offload_kv_cache_to_gpu`), и **выгружает все модели,
    находящиеся в данный момент в памяти сервера — из любого узла — перед загрузкой выбранной**,
    так что в VRAM остаётся только выбранная вами модель. Вам больше не нужно предварительно
    загружать модель в GUI LM Studio.
 - **Выходы:** `positive`, `negative`, `raw`, `scene_name`, `face_positive`, `face_negative`.
 - **`release_vram_after_run`** (по умолчанию вкл.) выгружает модель LM Studio после завершения
   работы узла, чтобы диффузионный конвейер вернул VRAM. Выключайте только если LLM и чекпоинт
   одновременно помещаются в VRAM.
- Включите **`generate_face_prompts`**, чтобы также получать короткие промпты только для лица
  для FaceDetailer/inpainting. Пустые поля лица автоматически откатываются к основным
  `positive`/`negative`.
- **`reuse_last_prompt`** возвращает кэшированный результат без вызова LLM (удобно для
  повторной отрисовки без перегенерации промпта). Примечание: выключите его, чтобы работал
  цикл авто-переработки.
- **`seed`** передаётся в запрос LLM (для серверов, которые его учитывают).
- **`max_field_retries`** (по умолчанию 2): если модель возвращает JSON-ответ с отсутствующими
  обязательными полями, узел переспрашивает полный ответ до этого количества раз. Пустой
  `scene_name` затем откатывается к slug от `positive`; пустые `positive`/`negative` вызывают ошибку.
- Кнопка **🔄 Обновить модели** перечитывает список моделей с сервера.
- **Стилевые пресеты** (`style_preset`): выберите встроенный стиль, чтобы добавить его стилевые
  теги к сгенерированному промпту (и переопределить системный промпт, когда виджет системного
  промпта оставлен по умолчанию). Пресеты, отказывающиеся от режима без негатива, в этом режиме
  пропускаются автоматически. Используйте «Reload presets» / «Reset to defaults» в меню узла
  для управления ими.
- **Расширенные опции** (`reasoning`, `flash_attention`, `offload_kv_cache_to_gpu`,
  `repeat_penalty`, `top_k`, `top_p`, `min_p`): передаются в нативный v1 API LM Studio, когда сервер
  их поддерживает. Оставленные по умолчанию сохраняют старое поведение, совместимое с OpenAI.
  `reasoning` включает рассуждения модели-thinking; `flash_attention` / `offload_kv_cache_to_gpu`
  — опции загрузки модели.

### LLM Prompt Studio Image Critic (Критик изображений)

Зрительная модель оценивает, насколько хорошо изображение соответствует промпту.
  - **Входы:** `image`, `prompt`, `server_url`, `api_key`, `model`, `load_model_profile`,
    `context_length`, `gpu_offload`, `critic_prompt`, `threshold`, `image_max_size`,
    `temperature`, `max_tokens`, `clear_notes_on_approve`, `auto_loop`, `max_retries`,
    `vision_check`, `revision_view`, `flash_attention`, `offload_kv_cache_to_gpu`,
    `release_vram_after_run`.
  - **`load_model_profile`** работает точно так же, как у Писателя (по умолчанию `auto`,
    универсальная рекомендация по размеру, `custom` сохраняет значения виджетов). Поскольку Критик
    всегда является зрительной моделью, его профиль расширяет вызов `chat_completion`
    рекомендованными параметрами сэмплирования (temperature / top_p / top_k / repeat_penalty /
    min_p / presence_penalty), но структурированный JSON-вывод никогда не используется с изображением.
  - **`Advanced settings` (Расширенные настройки)** (кнопка): как у Писателя — `context_length`,
    `gpu_offload`, `flash_attention`, `offload_kv_cache_to_gpu` **и виджеты сэмплирования**
    `temperature`, `max_tokens`, `repeat_penalty`, `top_k`, `top_p`, `min_p` скрыты за кнопкой
    **«⚙ Расширенные настройки»** (рядом с `load_model_profile`), свёрнуты по умолчанию;
    нажмите её, чтобы показать/скрыть.
   - **Выходы:** `approved` (bool), `score` (int), `revision_notes`, `verdict`, `raw`.
 - **`release_vram_after_run`** (по умолчанию вкл.) выгружает модель LM Studio после завершения
   работы узла, чтобы диффузионный конвейер вернул VRAM. Выключайте только если LLM и чекпоинт
   одновременно помещаются в VRAM.
- `approved = score >= threshold`. Подключите `approved` в Smart Save для фильтрации сохранения.
- **Цикл авто-переработки**: включите `auto_loop`, чтобы критик автоматически подавал свои
  `revision_notes` обратно в Писателя и ставил в очередь заново, пока изображение не пройдёт или
  не достигнут `max_retries`. Требует выключенного `reuse_last_prompt` у Писателя.
- Заголовок узла показывает текущий счёт и статус одобрения.

### LLM Prompt Studio Smart Save (Умное сохранение)

Сохраняет одобренные изображения как JPEG, опционально с метаданными в EXIF.
- **Входы:** `image`, `approved`, `filename_prefix`, `save_dir`, `jpeg_quality`,
  `auto_save_to_library`, `save_metadata_to_exif`, `library_path`, плюс опциональные
  `positive`, `negative`, `scene_name`, `face_positive`, `face_negative`.
- **Выходы:** нет (выходной узел).
- Сохраняет только когда `approved` истинно. Имя файла:
  `[prefix_]checkpoint[_lora1_lora2...]_NNNNN.jpg` (`NNNNN` авто-инкремент).
- EXIF (записывается когда `save_metadata_to_exif` включён, по умолчанию) хранит промпты,
  промпты лица, чекпоинт, LoRA и параметры сэмплера (теги и ASCII, и Unicode).
- Выключите **`save_metadata_to_exif`**, чтобы писать JPEG без метаданных — меньше файлы и
  лучше приватность (напр. при публичном обмене изображениями).
- Кнопка **💾 Сохранить промпт в библиотеку** записывает последний сохранённый промпт в библиотеку.

### LLM Prompt Studio Library Loader (Загрузчик библиотеки)

Загружает сохранённую сцену из библиотеки промптов.
- **Входы:** `library_path`, `scene_name` (комбо сохранённых сцен).
- **Выходы:** `positive`, `negative`, `scene_name`, `face_positive`, `face_negative`.
- Кнопка **🔄 Обновить список сцен** перечитывает библиотеку.

### LLM Prompt Studio Scene Builder (Конструктор сцен)

Двухэтапное построение сцены из изображения.
  - **Входы:** `stage` (`1 - describe` / `2 - compose`), `image`, `server_url`,
    `api_key`, `model`, `load_model_profile`, `context_length`, `gpu_offload`,
    `describe_prompt`, `composer_prompt`, `user_changes`, `image_max_size`, `temperature`,
    `max_tokens`,     `max_field_retries`, `vision_check`, `description_view`, `prompt_mode`,
    `family`, `architecture`, `flash_attention`, `offload_kv_cache_to_gpu`, `reasoning`, `repeat_penalty`,
    `top_k`, `top_p`, `min_p`, `release_vram_after_run`.
  - **`load_model_profile`** работает как у Писателя. Этап определяет «вид»: этап 1
    (`describe`) — проза из зрительного ввода, поэтому всегда `baseline` **без**
    структурированного вывода; этап 2 (`compose`) — это JSON-контракт Писателя и получает
    профиль `structured` (near-greedy ~0.1 + структурированный JSON) для моделей ≥7B, как у
    Писателя. `custom` сохраняет значения виджетов сэмплирования. `vision_check` применяется
    только к этапу 1 (анализ изображения) — этап 2 компонует по сохранённому текстовому
    описанию и не требует зрительной модели.
  - **`Advanced settings` (Расширенные настройки)** (кнопка): как у Писателя — `context_length`,
    `gpu_offload`, `flash_attention`, `offload_kv_cache_to_gpu` **и виджеты сэмплирования**
    `temperature`, `max_tokens`, `repeat_penalty`, `top_k`, `top_p`, `min_p` скрыты за кнопкой
    **«⚙ Расширенные настройки»** (рядом с `load_model_profile`), свёрнуты по умолчанию;
    нажмите её, чтобы показать/скрыть.
   - **`prompt_mode`** и **`family`** ведут себя точно как у Писателя: `auto` переключается на
    композиторный промпт без негатива для дистиллированных семейств чекпоинтов (подключённый
    `family`), что Smart Loader сообщает включая случай применения дистиллированной LoRA к
    базовому чекпоинту (он включает семейство LoRA в `detected_family`).
   - **`architecture`** (опционально, только этап 2) ведёт себя как у Писателя: адаптирует стиль
    токенов и добавляет архитектурно-специфичные негативы по умолчанию для `Flux` / `SD3` /
    `SD1.5` / `Pony` / `Illustrious` и принудительно включает режим без негатива для `Flux` / `SD3`.
 - **Выходы:** `positive`, `negative`, `scene_name`, `prompt_view`, `description`.
 - **`release_vram_after_run`** (по умолчанию вкл.) выгружает модель LM Studio после завершения
   работы узла, чтобы диффузионный конвейер вернул VRAM. Выключайте только если LLM и чекпоинт
   одновременно помещаются в VRAM.
  Этап 1 помещает зрительное описание в `description`; этап 2 составляет промпт.
- **`max_field_retries`** (по умолчанию 2): на этапе 2, если JSON модели пропускает обязательные
  поля, узел переспрашивает полный ответ; пустой `scene_name` откатывается к slug от `positive`.
- Кнопка **→ Отправить в Писатель** копирует описание/промпт в `idea` Писателя.
- Кнопка **🔄 Обновить модели** (как у Писателя/Критика) перечитывает список моделей с сервера.

### LLM Prompt Studio Smart Loader (Умная загрузка)

Загружает чекпоинт и автоматически обрабатывает дистиллированную LoRA.
- **Входы:** `ckpt_name`, `family_override`, `lora_name`, `apply_lora`,
  `strength_model`, `vae_user`.
- **Выходы:** `MODEL`, `CLIP`, `VAE_MODEL`, `VAE_USER`, `detected_family`,
  `detected_family_info`, `detected_architecture`, `detected_architecture_info`, `ckpt_name`.
- Определяет семейство чекпоинта по имени файла + метаданным safetensors:
  `base`, `dmd`, `lcm`, `turbo`, `hyper`, `lightning`, `flash` (плюс `schnell`/`tcd` → `turbo`,
  `pcm` → `lcm`). `family_override` принудительно задаёт его.
- `detected_family_info` — СТРОКА, описывающая **почему** выбрано это семейство, напр.
  `family: turbo | source: filename` — полезно при подключении `detected_family` во вход `family`
  Писателя и подтверждении, что детектор выбрал верное семейство.
- `apply_lora`: **`auto`** применяет LoRA только для `base` (недистиллированных) моделей,
  **`always`** принудительно применяет её, **`never`** пропускает.
- `VAE_USER` откатывается к встроенному VAE чекпоинта, когда `vae_user = [none]`.
  Используйте `VAE_USER` далее по цепочке, чтобы выход никогда не был пустым.
- Заголовок узла показывает обнаруженное семейство.

### LLM Prompt Studio Smart Parameters (Умные параметры)

Рекомендует параметры KSampler (`steps` / `cfg` / `sampler` / `scheduler`) по семейству чекпоинта,
чтобы не искать их вручную. Существует **одна** нода — она использует единый полный список
шедулеров (стандартные шедулеры ComfyUI плюс `AYS SD1` / `AYS SDXL` / `AYS SVD` / `GITS`), который
поддерживает собственный KSampler студии, поэтому никакого разделения на `target`/«Efficient» не
нужно.

- **Входы:** `family_override` (auto / семейство), `preset` (`user` / `balanced` / `speed` / `quality`),
  `steps`, `cfg`, `sampler_name`, `scheduler`, плюс опциональные `detected_family`
  (подключите сюда выход `detected_family` Smart Loader), `ckpt_name` и `architecture`
  (подключите выход `detected_architecture` Smart Loader).
- **Выходы:** `steps` (INT), `cfg` (FLOAT), `sampler_name` (COMBO), `scheduler` (COMBO), `info`
  (STRING).
- **Пресеты:** `user` пропускает введённые значения виджетов без изменений; `balanced` / `speed` /
  `quality` выбирают рекомендованную строку steps/cfg/sampler (quality — максимум шагов, speed —
  минимум).
- **Определение семейства:** эффективное семейство определяется в таком порядке — `detected_family`
  (если подключено, от Smart Loader; уже включает дистиллированную LoRA), затем `family_override`,
  затем автоопределение по **имени файла** чекпоинта, его метаданным safetensors и **имени родительской
  папки** (поэтому файл с общим именем внутри папки `Lightning/` всё равно распознаётся). Для
  известных чекпоинтов Lightning/Hyper число шагов также считывается из имени файла
  (`SDXL-Lightning_4step` → 4 шага).
- **AYS SDXL для дистиллированных семейств:** для дистиллированных семейств (lightning, hyper, dmd,
  turbo, lcm, tcd, pcm, flash, schnell) нода рекомендует **`AYS SDXL`** на пресетах `balanced`/`speed`;
  любое семейство из `model_meta.FAMILY_MARKERS`, у которого нет собственной строки, автоматически
  получает разумные общие дистиллированные значения по умолчанию.
- **Учёт архитектуры:** когда эффективное семейство — `base` и подключена известная `architecture`
  (SD1.5 / Pony / Illustrious / Flux / SD3), нода рекомендует собственные параметры сэмплера этой
  базовой архитектуры (например, Flux → 24 шага, cfg 1.0, euler/simple; SD1.5 → cfg 7.0) вместо
  SDXL-строки, чтобы не-SDXL чекпоинт не получал «размытый» результат. Дистиллированные семейства
  сохраняют приоритет и не переопределяются архитектурой.
- **Сентинелы:** оставьте `steps`/`cfg` равными `0`/`-1.0`, а `sampler_name`/`scheduler` — `auto`,
  чтобы использовать рекомендацию. Любое значение, введённое вручную, переопределяет рекомендацию и
  сохраняется при перезагрузке (веб-интерфейс автозаполняет только те виджеты, которые вы не правили).
- Веб-интерфейс автозаполняет виджеты из роута `/llm_prompt_studio/sampler_params` при изменении
  семейства/пресета/чекпоинта (роут также принимает `arch`).

### LLM Prompt Studio Smart Multi-Clip

Кодирует до четырёх пар промптов одним CLIP с общими настройками размера. Учитывает архитектуру:
подключите `detected_architecture` от Smart Loader во вход `architecture`, чтобы не-SDXL чекпоинты
кодировались корректно.
- **Входы:** `clip`, `width`, `height`, `crop_w`, `crop_h`, и опциональные
  `target_width`, `target_height`, `positive1_g/l`, `negative1_g/l`,
  `positive2_g/l`, `negative2_g/l`, и `architecture`.
- **Выходы:** `clip` (пропускание), `positive1`, `negative1`, `positive2`, `negative2` (CONDITIONING).
- Каждый `*_l` откатывается к своему `*_g` когда пуст; `target_*` откатываются к
  `width`/`height` когда пусты; пустая пара кодирует пустую строку.
- **Кондиционирование по архитектуре:**
  - **SDXL / Pony / Illustrious** — двойное g/l-кондиционирование (исходное поведение).
  - **SD1.5** — кодируется через свой одиночный энкодер; метаданные width/height добавляются, но
    игнорируются SD1.5 (безвредно).
  - **Flux / SD3** — кондиционирование «наилучшего усилия» (выводится предупреждение с
    рекомендацией использовать родные `CLIPTextEncodeFlux` / `CLIPTextEncodeSD3` для качества);
    метаданные width/height добавляются, но игнорируются этими моделями.
  - Если `architecture` не подключён, нода смотрит на форму энкодера самого CLIP (dual или
    single) и ветвится соответственно, поэтому существующие SDXL-графы не меняются.
- Заменяет несколько узлов `CLIPTextEncodeSDXL`: `positive1/negative1` → основной KSampler,
  `positive2/negative2` → FaceDetailer.

## Шаблоны промптов и стилевые пресеты (`presets_default.json`)

Все системные промпты по умолчанию и все стилевые пресеты живут в **одном файле**,
**`presets_default.json`** в корне пакета — редактируйте их, не трогая Python. Он имеет два
раздела верхнего уровня:

- **`defaults`** — базовые системные промпты, используемые когда стилевой пресет не выбран. Ключи:

| Ключ | Используется |
|-----|---------|
| `reasoning_hint` | добавляется к writer/critic/composer (очистите, чтобы отключить) |
| `writer_system` | Prompt Writer |
| `face_instruction` | Prompt Writer (промпты лица) |
| `critic_system` | Image Critic |
| `describe` | Scene Builder (этап 1) |
| `composer` | Scene Builder (этап 2) |
| `writer_system_no_negative` | Prompt Writer (дистиллированный/режим без негатива; откат к `writer_system`) |
| `composer_no_negative` | Scene Builder (дистиллированный/режим без негатива; откат к `composer`) |
| `face_instruction_no_negative` | Промпты лица Prompt Writer (режим без негатива; откат к `face_instruction`) |

- **`presets`** — 51 стилевой пресет, перечисленный в комбобоксе `style_preset` Писателя
  (см. [Стилевые пресеты](#стилевые-пресеты)). Когда комбобокс оставлен на «— none —», Писатель
  использует промпт `defaults.writer_system`; когда выбран пресет, его `system_prompt` (или
  `system_prompt_no_negative` в режиме без негатива) переопределяет его, а его `style_tags`

Оба раздела копируются вместе в редактируемый пользователем файл
**`llm_prompt_studio_presets.json`** в директории вывода ComfyUI при первом запуске
(используйте «Reset to defaults» для восстановления). Изменения вступают в силу после перезапуска
ComfyUI (шаблоны загружаются при старте). Каждый узел также предоставляет свой промпт как
редактируемый виджет, так что вы можете переопределять его для каждого узла.

## Библиотека промптов

Одобренные промпты могут храниться в JSON-библиотеке (по умолчанию
`output/llm_prompt_studio_library.json`). Каждая запись хранит `prompt`, `negative_prompt`,

**все четыре** поля совпадают с существующей записью, так что два промпта с одинаковым positive, но
разными промптами лица, сохраняются оба. Записи сериализуются блокировкой на файл и являются
атомарными (`.tmp` + переименование); предыдущий файл сохраняется как `*.json.bak` для восстановления.
Загружайте их обратно через **Library Loader**.

## Стилевые пресеты

Комбобокс `style_preset` Писателя перечисляет ~50 встроенных стилей, сгруппированных по категориям
(Фотография, Художественные течения, Азиатское искусство, Традиционные медиа, Цифровое и
современное, Фэнтези и хоррор, Эпохи и стили, Базовые стили); каждая запись показывается как
`Категория > Название`. Исходные 14 стилей сохраняют свои названия, поэтому рабочие процессы,
сохранённые с «голым» названием пресета, по-прежнему разрешаются. При выборе:

- добавляются `style_tags_positive` / `style_tags_negative` пресета к сгенерированным
  `positive` / `negative` (пропускается для `negative` в режиме без негатива);
- системный промпт переопределяется `system_prompt` пресета **только когда** виджет системного
  промпта оставлен по умолчанию. В режиме без негатива используется выделенный вариант пресета
  `system_prompt_no_negative` (он требует пустых `negative` / `face_negative`), так что стиль
  пресета всё равно применяется, не противореча режиму.

Системный промпт каждого пресета несёт блок **«Engineering rules» (Правила инженерии)** (полученный
из практики SDXL-промпт-инжиниринга): компонуйте чёткими слоями (субъект → внешность → действие/поза
→ отношения объектов → окружение → композиция → камера/объектив → освещение → цветовая палитра →
настроение → стиль), начинайте с главного субъекта, предпочитайте конкретные визуальные описатели
абстрактным усилительным прилагательным, держите негативы короткими и целенаправленными, и
(опционально) взвешивайте только самую важную черту как `(concept:1.1)`–`(concept:1.3)`. NSFW
полностью разрешён — интимный контент должен описываться анатомически корректными, точными
терминами и никогда не цензурируется.

Пресеты копируются из `presets_default.json` в редактируемый `llm_prompt_studio_presets.json`
в директории вывода ComfyUI при первом запуске. Используйте пункт меню узла **«Reload presets»**,
чтобы обновить комбо после редактирования этого файла, и **«Reset to defaults»**, чтобы восстановить
поставляемый набор («Copy presets path» помещает расположение файла в буфер обмена). Пресет с
`disabled_in_no_negative_mode` автоматически пропускается в режиме без негатива.

## Цикл авто-переработки

С включённым `auto_loop` у Критика пакет автоматически замыкает цикл переработки:

1. Писатель генерирует промпт → изображение отрисовывается → Критик оценивает его.
2. Если отклонено, `revision_notes` Критика внедряются в виджет `revision_notes` Писателя и
   рабочий процесс ставится в очередь заново.
3. Писатель регенерирует исправленный промпт, изображение перерисовывается, Критик переоценивает.
4. Повторяется, пока не `approved` или не достигнут `max_retries` (счётчик сбрасывается при одобрении).

Требования: `reuse_last_prompt` ВЫКЛ у Писателя, и `revision_notes` НЕ подключён как графовое ребро
от Критика к Писателю (обратная связь внедряется через виджет, чтобы избежать цикла в графе
исполнения).

## Безопасность

Внешний ввод валидируется для снижения риска SSRF и обхода путей. Обе защиты строги по умолчанию
и могут быть ослаблены флагом, если вам нужны удалённые серверы или пути вне папки вывода.

- **`server_url` (защита от SSRF)** — разрешены только `http`/`https` и локальные/частные хосты
  (`localhost`, loopback, RFC-1918, link-local). Чтобы использовать удалённый/публичный сервер
  LM Studio, установите переменную окружения `LLM_PROMPT_STUDIO_ALLOW_PUBLIC=true`
  (или присвойте `ALLOW_PUBLIC_SERVER_URLS = True` напрямую в `lm_http.py`).
- **`library_path` / `save_dir` (защита от обхода путей)** — ограничены директорией вывода ComfyUI.
  Чтобы разрешить пути вне неё, установите `RESTRICT_PATHS_TO_OUTPUT = False` в `library.py`.
- **Глобальный кэш ответов LLM** — выключен по умолчанию. Установите `LLM_PROMPT_STUDIO_LLM_CACHE=true`,
  чтобы повторно использовать идентичные ответы chat-completion в рамках сессии (ограниченный LRU,
  ~256 записей). Ключ кэша исключает API-ключ и располагается ниже кэша `reuse_last_prompt` узла.
- **Освобождение VRAM после прогона LLM** — включено по умолчанию. Каждый LLM-узел (Writer,
  Image Critic, Scene Builder) выгружает свою модель LM Studio по завершении, чтобы диффузионный
  конвейер (KSampler Hires Fix / Face Detailer) получил VRAM обратно, а видовая модель могла
  загрузиться после этапа сэмплирования. Булев виджет **`release_vram_after_run`** (в ⚙ Advanced
  settings, по умолчанию **true**) управляет этим для узла; установите **false**, чтобы держать
  модель в памяти (например, при достаточном объёме VRAM для LLM и чекпоинта одновременно).
  Глобальный выключатель `LLM_PROMPT_STUDIO_KEEP_MODEL_LOADED=1` отключает освобождение везде без
  правки узлов. Каждое освобождение стоит одной перезагрузки (~5–10 с на типичном железе, GGUF
  остаётся в page-кэше ОС), поэтому повторные прогоны меняют немного задержки на защиту от CUDA OOM
  на малых GPU.
- Библиотека промптов записывается атомарно (`.tmp` затем переименование) во избежание повреждения.

## Отладочное логирование и расширенные опции

### Отладочное логирование

Логирование ВЫКЛ по умолчанию. Чтобы включить, отредактируйте `debug.py` в корне пакета и установите
`DEBUG_LEVEL` (требуется перезапуск ComfyUI):

- `MINIMAL` — логирует вход/выход/ошибку узла.
- `FULL` — добавляет запросы/ответы HTTP и попытки парсинга JSON.

Ротируемый лог пишется в `llm_prompt_studio.log` в директории вывода ComfyUI только когда
логирование активно. API-ключи (Bearer-токены, поля `api_key`) и base64-блобы изображений
маскируются или усекаются и никогда не пишутся целиком.

### Нативный LM Studio v1 API и расширенные опции

Узлы вызывают нативный эндпоинт LM Studio `/api/v1/chat` (и `/api/v1/models/load` для
`flash_attention` / `offload_kv_cache_to_gpu`) как для текстовых, так и для зрительных промптов.
Нативный эндпоинт отправляет системный промпт как верхнеуровневый `system_prompt`, рендерит
содержимое сообщений как типизированные части `input` (текст + `data_url` изображения) и устанавливает
`store: false`, чтобы LM Studio не хранил состояние диалога на сервере. Расширенные виджеты —
`reasoning`, `flash_attention`, `offload_kv_cache_to_gpu`, `repeat_penalty`, `top_k`, `top_p`, `min_p`
— передаются на эти эндпоинты, когда сервер их поддерживает. `reasoning` отправляется только когда
модель действительно его exposes (обнаружено через `capabilities.reasoning.allowed_options`); если
сервер отвергает его, вызов повторяется один раз без него. Маршрут OpenAI `/chat/completions`
сохранён только как изящный fallback (напр. когда нативное зрение отвергнуто). Загрузки моделей
устойчивы: если сервер отвергает опциональный параметр загрузки (напр. `gpu_offload` на некоторых
сборках), этот ключ отбрасывается и загрузка всё равно проходит; перед загрузкой модели
**каждый загруженный экземпляр выгружается через его `instance_id`**, так что остаётся резидентной
только выбранная модель.

Список моделей кэшируется **по URL сервера LM Studio** (ключ кэша — только URL; API-ключ никогда не
  сохраняется). **🔄 Обновить модели** наполняет комбо для этого сервера; каждый узел обновляет только
  список своего сервера, поэтому несколько серверов не пересекаются. Это же обновление больше не
  перезаписывает модель, выбранную вами в данный момент.

**Живой статус сервера.** Писатель / Критик изображений / Конструктор сцен показывают виджет
`server_status` (включён по умолчанию), который опрашивает маршрут пакета `GET /llm_prompt_studio/status`
каждые несколько секунд и сообщает `● Подключено — <имена загруженных моделей>`,
`● Подключено (модель не загружена)` или `● Сервер недоступен`. Модели-эмбеддинги, возвращаемые
списком моделей LM Studio, отфильтровываются, поэтому никогда не появляются как чат-модели в комбо.

## Типичный рабочий процесс

1. **Писатель** генерирует промпт из вашей идеи.
2. Промпт → ваш граф сэмплирования SDXL (используйте **Smart Loader** + **Multi-CLIP SDXL**).
3. Отрисованное изображение → **Критик** (зрительная модель оценивает его).
4. `approved` → **Smart Save** (сохраняет только хорошие изображения).
5. Включите **`auto_loop`** у Критика для автоматической доработки, либо подключите
   `revision_notes` вручную для ручного контроля.
6. Опционально сохраните промпт в **библиотеку** и перезагрузите его позже.

## Примечания и устранение неполадок

- **Нет модели в комбо?** Нажмите **🔄 Обновить модели** у Писателя/Критика и убедитесь, что сервер
  LM Studio запущен по `server_url`.
- **Критик говорит, что модель не поддерживает зрение?** Выберите VL-модель или снимите
  `vision_check`.
- **Текст рассуждений просачивается в результаты?** Пакет откатывается к `reasoning_content`
  модели, когда обычное поле `content` пусто, поэтому вывод thinking может попасть в результаты.
  Отключите thinking/рассуждения для этой модели в LM Studio, чтобы получить чистый вывод.
- **Заполнители** вроде `— server unavailable —` означают, что сервер недоступен.
- **Модель забывает сгенерировать некоторые JSON-поля?** Писатель и Конструктор сцен (этап 2)
  обнаруживают отсутствующие обязательные поля (`positive`, `negative`, `scene_name` и поля лица
  когда запрошены) и автоматически переспрашивают модель до `max_field_retries` раз для полного
  ответа. Если `scene_name` всё ещё отсутствует, он откатывается к slug от `positive`; если
  `positive`/`negative` всё ещё отсутствуют, узел вызывает ошибку. Если ваша модель продолжает
  опускать поля, увеличьте `max_field_retries` или переключитесь на модель с лучшим следованием
  инструкциям (промпты `writer_system` / `composer` уже требуют все поля).
- Логи используют Python `logging` под логгером `llm_prompt_studio` с префиксом `[LLMPromptStudio]`.
  Понизьте уровень этого логгера до DEBUG, чтобы видеть тайминги вызовов LLM и активность кэша.
