## [1.1.9] — 2026-08-19

Исправлен фатальный крах в ноде **KSampler Hires Fix** при дробном апскейле латента и
усилена устойчивость latent/pixel-путей апскейла.

### Исправлено
- **`Fatal Python error: Aborted` при `hires_upscale_type = latent` и дробном коэффициенте
  (напр. `hires_latent_upscale_factor = 1.25`, `bislerp` / `nearest-exact` / …).** `_latent_interp`
  передавал **размеры ячеек латента** напрямую в `LatentUpscale`, который трактует свои
  `width`/`height` как **пиксельные** и делит на 8 — из латента 64×64 получалось ~10×10
  (1/64 от нужной площади), и forward UNet аварийно завершался на вырожденном тензоре. Теперь
  целевой размер переводится обратно в пиксели (`w * 8`, `h * 8`), давая корректный
  апскейленный латент (проверено для 1.25×, 1.5×, 2.0×).
- **`pixel (model)` давал латент неверного размера / искажённый.** Декодированный тензор
  пикселей (BHWC) подавался прямо в `tiled_scale`, ожидающий NCHW. Теперь он переставляется
  BHWC → NCHW до апскейла и обратно в BHWC перед повторным кодированием.
- **В выпадающем списке `latent (model)` были невалидные модели.** Он объединял список папки
  `upscale_models` (пиксельные ESRGAN `.safetensors`) с латентными ресайзерами проекта, из-за
  чего пиксельная модель могла выбираться как `LatentUpscaleModel` и падать. Теперь в списке
  **только латентные ресайзеры проекта** (`models/upscale_models` — ttl-nn `sd15_resizer.pt` /
  `sdxl_resizer.pt`); об этом сказано в подсказке. Сломанные City96
  `latent-upscaler-v2.1_*.safetensors` удалены из `models/upscale_models`.

### Изменено
- Тест `test_project_local_helpers` теперь проверяет, что поставляемые латентные ресайзеры —
  `.pt` (City96 `.safetensors` удалены), а не `.safetensors`.

## [1.1.8] — 2026-08-18

Семейство-зависимые пресеты дистиллированных сэмплеров для ноды Smart Parameters, а также
автоопределение семейства чекпоинта и более понятные подсказки интерфейса ноды.

### Добавлено
- **Пресеты дистиллированных сэмплеров.** Нода Smart Parameters теперь рекомендует steps/cfg/sampler
  по семейству чекпоинта (lightning, hyper, dmd, turbo, lcm, tcd, pcm, flash, schnell) и переключает
  дистиллированные семейства на шедулер **AYS SDXL** на пресетах `balanced`/`speed` (собственный
  KSampler студии поддерживает AYS). Разделение на `target`/«Efficient» удалено — везде используется
  один полный список шедулеров (стандартные + AYS SD1/SDXL/SVD + GITS).
- **Общий дистиллированный запасной вариант.** Любое семейство из `model_meta.FAMILY_MARKERS`
  автоматически получает разумные дистиллированные значения по умолчанию, даже без собственной строки
  в таблице.
- **Автоопределение семейства по пути.** `detect_checkpoint_family()` теперь также сканирует имя
  родительской папки чекпоинта, поэтому файлы с общими именами внутри папки с именем семейства всё
  равно распознаются.
- **Самоопределение ноды.** Если не заданы `detected_family`/`family_override`, нода автоопределяет
  семейство по имени файла чекпоинта, метаданным и папке.
- **Подсказки интерфейса ноды.** Добавлено `DESCRIPTION` ноды и подсказки (tooltips) на входах
  family/preset/ckpt_name.

### Изменено
- Роут `sampler_params` Smart Parameters и автозаполнение веб-интерфейса обновлены под единый список
  шедулеров (без `target`).

## [1.1.7] — 2026-08-18

Сделано так, чтобы каждая нода корректно работала с не-SDXL чекпоинтами (SD1.5 / SD3 / Flux /
Pony / Illustrious), а также переименована **Multi-CLIP SDXL** → **Smart Multi-Clip**. Все новые
входы опциональны со значением по умолчанию `""`, поэтому существующие графы (по ключу регистрации
`LLMPromptStudioMultiClipSDXL`, который не менялся) продолжают загружаться и показывают новое имя.

### Добавлено
- **Учёт архитектуры в Smart Parameters.** Новый опциональный вход `architecture` (подключите
  `detected_architecture` от Smart Loader) заставляет ноду рекомендовать собственные параметры
  сэмплера базовой архитектуры для базовых чекпоинтов — например, Flux → 24 шага / cfg 1.0 /
  euler-simple, SD1.5 → cfg 7.0, SD3 → 40 шагов / cfg 4.5, Pony / Illustrious → 28 шагов / cfg 6.0.
  Дистиллированные семейства сохраняют приоритет и не переопределяются архитектурой. Роут
  `sampler_params` также принимает `arch`.
- **`resolve_architecture()` в `model_meta.py`.** Определяет каноническую базовую архитектуру по
  загруженному объекту модели (и конфигу), с уточнением, восстанавливающим **Pony / Illustrious**
  из имени файла SDXL-чекпоинта, не перезаписывая при этом настоящее обнаружение Flux / SD3 / SD1.5.
- **`force_no_negative` теперь работает.** В `presets_default.json` уже было `force_no_negative`
  для Flux / SD3; Писатель и Конструктор сцен теперь учитывают его (вычисляется до разрешения
  no-negative), так что эти архитектуры принудительно дают пустой негатив независимо от семейства.

### Изменено
- **Multi-CLIP SDXL → Smart Multi-Clip.** Теперь принимает вход `detected_architecture` и ветвит
  кондиционирование по архитектуре: SDXL / Pony / Illustrious используют dual g/l; SD1.5 — свой
  одиночный энкодер; Flux / SD3 выдают кондиционирование «наилучшего усилия» с предупреждением,
  рекомендующим родные `CLIPTextEncodeFlux` / `CLIPTextEncodeSD3`. Защитная сетка токенов
  предотвращает `KeyError` на одиночных энкодерах CLIP. Если не подключено — поведение прежнее
  (по форме энкодера CLIP).

### Исправлено
- Конструктор сцен теперь передаёт свой вход `architecture` в построитель промпта (ранее был
  объявлен, но не проброшен), так что адаптация по архитектуре реально применяется на этапе 2.

## [1.1.6] — 2026-08-18

Улучшения, заимствованные у родственных проектов (pinkpixel-dev/comfyui-llm-prompt-enhancer,
jideka/ComfyUI-SmartPromptCrafter); всё добавлено аддитивно и изолировано, так что текущее
поведение не меняется.

### Добавлено
- **Определение архитектуры в Smart Loader.** Два новых выхода `detected_architecture` и
  `detected_architecture_info` сообщают базовую архитектуру (SDXL / SD1.5 / Pony / Illustrious /
  Flux / SD3 / unknown), определяемую по загруженному объекту модели с запасным вариантом по
  имени файла. SDXL остаётся каноничным, когда архитектура не подключена.
- **Адаптация промптов под архитектуру (Писатель / Конструктор сцен).** Новый необязательный
  вход `architecture` добавляет спец-дополнение к системному промпту и (в стандартном режиме)
  негативы по умолчанию; Flux / SD3 принудительно включают режим без негатива. Настройки лежат в
  `presets_default.json` (`architecture_guidance`) и редактируются пользователем.
- **Категоризированная библиотека стилевых пресетов.** 14 плоских пресетов теперь сгруппированы
  в ~50 стилей с метками `Категория > Название`; исходные 14 названий сохранены, поэтому старые
  рабочие процессы разрешаются. Подбор пресета принимает и «голое» имя, и категоризированную метку.
- **Необязательный глобальный кэш ответов LLM** (`lm_http.py`). Выключен по умолчанию; включается
  `LLM_PROMPT_STUDIO_LLM_CACHE=true`. Идентичные запросы (без API-ключа) отдаются из ограниченного
  LRU (~256 записей) ниже кэша `reuse_last_prompt` узла.

### Изменено
- `RETURN_TYPES`/`RETURN_NAMES` Smart Loader дополнены двумя выходами (`detected_architecture`,
  `detected_architecture_info`); существующие связи не затрагиваются.

## [1.1.5] — 2026-08-18

Добавлены ноды **LLM Prompt Studio Smart Parameters**, которые рекомендуют параметры KSampler
(steps / cfg / sampler / scheduler) по определённому семейству чекпоинта.

### Добавлено
- **Нода `LLM Prompt Studio Smart Parameters`** — выдаёт `steps`, `cfg`, `sampler_name`,
  `scheduler` (COMBO) и `info`, подключаемые напрямую к обычному `KSampler`. Полная обратная
  совместимость: список шедулеров не содержит AYS/GITS.
- **Нода `LLM Prompt Studio Smart Parameters (Efficient)`** — те же выходы, но COMBO шедулера
  также включает `AYS SD1 / AYS SDXL / AYS SVD / GITS`, поэтому линкуется к Efficient KSampler
  (jags111). Для дистиллированных семейств рекомендует `AYS SDXL` на пресетах balanced/speed.
- Рекомендованные параметры для `base`, `lightning`, `hyper`, `dmd`, `turbo`, `lcm`, `tcd`,
  `pcm`, `flash`, `schnell` по трём пресетам (`balanced` / `speed` / `quality`) в
  `nodes/_distilled_presets.py` (чистый Python, без импорта `comfy` — тестируется headless).
- **Роут `GET /llm_prompt_studio/sampler_params`** возвращает рекомендацию для заданных
  `family` / `preset` / `ckpt` / `target`; веб-интерфейс вызывает его для автозаполнения виджетов.
- Автозаполнение в вебе: при создании и при изменении `detected_family` / `family_override` /
  `preset` / `ckpt_name` нода запрашивает рекомендации и заполняет редактируемые виджеты — кроме
  случая ручного редактирования виджета (dirty-флаг сохраняется). Сентинел `auto` внедряется в
  сохранённые workflow, чтобы загрузка никогда не выдавала «Value not in list».

### Удалено
- Ничего.

## [1.1.4] — 2026-08-17

Обзор корректности оценки `update3`/`update4` (`plans/update3.md`, `plans/update4.md`).
Все утверждения проверены по исходному коду; этот релиз применяет валидные исправления и
явно игнорирует не являющиеся ошибками пункты.

### Исправлено
- **Ключ кэша повторного использования Писателя был слишком узким (B1).** `nodes/writer.py`
  кэшировал только по `(unique_id, prompt_mode)`, поэтому смена `style_preset`/`system_prompt`/
  `idea`/`revision_notes`/`generate_face_prompts`/`face_prompt_instruction` молча возвращала
  устаревший промпт. Ключ кэша теперь включает эти входы. `family` намеренно остаётся исключённым,
  чтобы переключение чекпоинта всё равно переносило промпты в режиме повторного использования.
- **Определение семейства безусловно пропускало каждое совпадение `flash`, когда `flash_attention`
  встречалось где угодно (B2).** В `model_meta.py` семейство `flash` теперь пропускается только для
  точного вхождения подстроки `flash_attention`, поэтому реальный чекпоинт Flash (напр. `FlashSDXL`,
  `SDXLFlash`) всё ещё определяется корректно.
- **Нативная ошибка HTTP v1 игнорировала контекст изображения (B3).** `lm_http.py` жёстко
  прописывал `has_images=False` в `_enrich_http_error`; `_chat_v1` теперь выводит `has_images` из
  сообщений запроса, так что подсказка «модель не поддерживает ввод изображений» срабатывает для
  отклонений зрения.
- **Повторная попытка полей молча откатывалась к обычному тексту (B4).** Повторные вызовы
  `parse_prompt_json` в `nodes/writer.py` и `nodes/scene_builder.py` теперь передают
  `allow_plain_text_fallback=False`, совпадая с начальным вызовом (неправильный ответ повтора не
  должен трактоваться как валидный промпт).
- **Выход `prompt_view` этапа 1 Конструктора сцен был пустым (D1).** Этап 1 теперь возвращает
  описание в слоте `prompt_view` (`("", "", "", description, description)`).
- **Продублированное предложение NSFW в пресете Аниме (C1).** В `presets_default.json` предложение
  «Explicit and intimate content is fully authorized…» встречалось дважды в обоих вариантах
  (стандартном и без негатива) Аниме; дубликат удалён.

### Изменено
- **Уточнён `_is_reasoning_rejection` (B5).** Скобки делают приоритет операторов проверок
  отклонения зрения `and`/`or` явным (без изменения поведения).

### Удалено
- **Неиспользуемый параметр `require_face_negative` (D2).** `parsing.find_missing_fields` больше
  не принимает мёртвый параметр; у него не было реальных вызывающих, а поля лица намеренно не
  трактуются как отсутствующие.

### Документация
- **Исправлен комментарий `combos.combo_models` (D3).** Утверждение «ограничено своим server_url»
  было неточным: `INPUT_TYPES` может выразить только `DEFAULT_SERVER` по умолчанию, поэтому
  кэш по URL достигается с этим значением по умолчанию во время построения, а реальный `server_url`
  узла применяется через виджет во время выполнения.
- **Пункты #1–#8 `update4` были рассмотрены и проигнорированы.** #3 (безусловное обнаружение LoRA
  в Smart Loader) ЛОЖНО — обнаружение уже защищено проверкой
  `if should_apply and lora_name and lora_name != "[none]"`; #1, #2, #4, #5, #6, #7, #8 являются
  намеренными/по замыслу и не требуют изменений.

## [1.1.3] — 2026-08-17

### Исправлено
- **`WRITER_RESPONSE_SCHEMA` требовал непустой `negative` даже в режиме без негатива
  (дистиллированном).** Строгая JSON-схема в `nodes/model_recommendations.py` больше не перечисляет

  «взят из бенчмарка для этой модели», но рекомендация — универсальная эвристика по размеру без
  жёстко заданного списка моделей. Подсказка теперь так и говорит в Писателе / Критике изображений /
  Конструкторе сцен.

### Изменено
- **README теперь перечисляет все входы Писателя и документирует полное сворачивание
  расширенных настроек.** `load_model_profile` и `server_status` добавлены в список входов Писателя,
  а описание расширенных настроек теперь гласит, что виджеты сэмплирования (`temperature`,
  `max_tokens`, `repeat_penalty`, `top_k`, `top_p`, `min_p`) сворачиваются вместе с регулировками
  загрузки (это уже соответствовало `web/js/llm_prompt_studio_actions.js` `ADVANCED_WIDGETS`).
- **`reasoning` теперь часть свёрнутого блока расширенных настроек** (`ADVANCED_WIDGETS` в
  `web/js/llm_prompt_studio_actions.js`), поэтому он скрывается вместе с другими регулировками
  сэмплирования.

### Добавлено
- **Явное логирование разрешённого профиля сэмплирования.** Писатель логирует имя эффективного
  профиля и финальные параметры сэмплирования (temperature / top_p / top_k / min_p / repeat_penalty /
  presence_penalty / reasoning / флаг structured) после разрешения `load_model_profile`.

## [1.1.1] — 2026-08-17

### Исправлено
- **`face_negative` был непустым в режиме без негатива (дистиллированном).** Когда `prompt_mode`
  был `auto`/`no_negative`, Писатель (`nodes/writer.py`) принудительно сбрасывает и `face_negative`,
  и `negative` в пустоту, как только выбран композитор без негатива (негатив инертен при CFG~1 и
  должен оставаться согласованным). Ранее устаревший `face_negative` просачивался в промпт даже при
  пустом `negative`, противореча сэмплированию CFG~1 (игнорируется негатив). Конструктор сцен
  (`nodes/scene_builder.py`) выставляет только выходы `positive`/`negative` — его поля лица
  парсятся, но не выводятся, — поэтому он сбрасывает `negative` в пустоту в режиме без негатива, но
  не имеет выхода `face_negative`, который мог бы просочиться.
- **Определение семейства чекпоинта пропускало несколько дистиллированных семейств.** `model_meta.py`
  теперь сопоставляет `schnell`, `tcd` и `pcm` с их базовыми дистиллированными семействами
  (SD1.5 `schnell`/`tcd` → `turbo`; `pcm` → `lcm`), и ключ подсказки свободного текста метаданных
  исправлен с `"tags"` на `"tag"`. Верхний регистр токена семейства на/после границы принимается
  безусловно, а защита `flash_attention` больше не подавляет реальное совпадение семейства.

### Добавлено
- **Выход `detected_family_info` Smart Loader.** `nodes/smart_loader.py` теперь также возвращает
  `detected_family_info` (STRING), описывающий происхождение обнаруженного семейства, напр.
  `family: turbo | source: filename` / `source: metadata` / `source: base` / `source: override`.
  `detected_family` сообщает только собственное семейство чекпоинта (загруженная на базовый
  чекпоинт дистиллированная LoRA не меняет его). Хелпер `model_meta.detect_checkpoint_family_info()`
  возвращает `(family, source)` и экспортируется в `model_meta.__all__`.
- **Индикатор статуса сервера LM Studio.** Писатель / Критик изображений / Конструктор сцен получили
  опциональный виджет `server_status` STRING, который опрашивает `GET /llm_prompt_studio/status`
  каждые 3 с (через `lm_http.server_status()` и новое действие `pollServerStatus`) и показывает
  `● Подключено — <имена загруженных моделей>`, `● Подключено (модель не загружена)` или
  `● Сервер недоступен`. Маршрут добавлен в `server_routes.py`; `refreshModels` больше не затирает
  текущий выбор модели пользователя.
- **Модели-эмбеддинги отфильтрованы из комбо моделей.** `lm_http.fetch_models` / `_parse_native_models`
  теперь пропускают любую запись с `"type": "embedding"` (как на нативном пути `/api/v1/models`, так
  и на fallback OpenAI `/v1/models`), поэтому текстовые/эмбеддинг-модели LM Studio больше не
  появляются как чат-модели.

### Изменено

## [1.0.2] — 2026-08-13

### Исправлено
- **Предзагрузка модели использовала некорректный URL (`/v1/api/v1/models/load`) и молча ничего не
  делала.** `load_model` строил нативный эндпоинт загрузки v1 LM Studio из `server_url` без отрезания

  `flash_attention` / `offload_kv_cache_to_gpu` никогда не применялись. `load_model` теперь отрезает
  конечный `/v1` через существующий хелпер `_server_root()` (совпадая с `_chat_v1` и
  `maybe_unload_old`), поэтому эндпоинт корректен `/api/v1/models/load`, и модели предзагружаются

  `dmd2`) сообщались как `base`, так что режим `no_negative` никогда для них не включался
  автоматически. Определение теперь чувствительно к регистру: слово семейства принимается как
  самостоятельный токен или CamelCase/версионное продолжение (`HyperSDXL`, `LCMXL`, `dmd2`), всё ещё
  отвергая маркеры, склеенные в более длинное строчное слово (`hypernetwork`, `calcium`,
  `flash_attention`). Версионированные варианты (`dmd2`) сопоставляются с семейством `dmd`.
- **Определение семейства чекпоинта давало ложные положительные из свободного текста метаданных.**
  Сканировался весь JSON метаданных safetensors (включая `description`/`comments`), поэтому базовая
  модель, чьё описание говорило «hyper-realistic» / «lightning-fast» / «turbo-charged», ложно
  помечалась как дистиллированная. Сканирование теперь использует только структурированные поля
  метаданных и исключает ключи свободного текста, поэтому описания больше не могут вызвать ложное
  совпадение семейства (структурированные поля вроде `modelspec.title` всё ещё учитываются).
- **Писатель тратил токены, выдавая поля лица, когда они не запрашивались.** Базовые промпты
  `writer_system` / `writer_system_no_negative` предписывали `face_positive` / `face_negative` в
  каждом ответе и показывали их в JSON-примере, поэтому модель возвращала их даже при выключенном
  `generate_face_prompts`. Промпты теперь помечают поля лица как ОПЦИОНАЛЬНЫЕ — включены только когда
  запрошена генерация промптов лица, иначе опущены (`parse_prompt_json` уже по умолчанию даёт

## [0.7.1] — 2026-08-10

### Исправлено
- **Падение RGBA/альфа в Критике и Конструкторе сцен**: `imaging.image_to_base64` теперь конвертирует
  изображение в `RGB` перед JPEG-кодированием, совпадая с `smart_save.py`. Ранее тензор с альфа

- **Перекрёстное загрязнение списков моделей между серверами**: сборщик комбо больше не сливает
  модели, кэшированные для *других* пар `server_url`/`api_key`, в выпадающий список.
- **Парсинг JSON ломался на фигурных скобках внутри строковых значений**: `_iter_brace_objects`
  теперь отслеживает строковые литералы JSON (и экранирования `\`), поэтому промпты, содержащие `{`/`}`

### Изменено
- Список моделей теперь различает **сервер недостижим** (`— server unavailable —`) и **сервер
  достижим, но модели не загружены** (`— no models on server —`). `lm_http.get_cached_models`
  возвращает последнее, когда сервер отвечает пустым списком, а JS `refreshModels` использует
  `PH_EMPTY` (`— no models on server —`) когда сервер поднят, но ничего не перечисляет. Ранее
  неиспользуемые константы `PLACEHOLDER_EMPTY` / `PH_EMPTY` теперь подключены.

### Документация
- Разделы README «Требования» и «Примечания и устранение неполадок» плюс запись журнала 0.6.0 теперь
  точно описывают fallback рассуждений: когда модель возвращает пустой `content`, но непустой

    параллельных записях.
