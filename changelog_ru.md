# Журнал изменений (Changelog)

Все значимые изменения **ComfyUI LLM Prompt Studio** задокументированы здесь.
Формат основан на [Keep a Changelog](https://keepachangelog.com/),
и проект следует [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Добавлено
- **Система папки `Styles/` (заменяет единый `presets_default.json`).** Все 162 пресета стилей
  теперь хранятся отдельными JSON-файлами в `Styles/` (по одному файлу на направление), базовые
  промпты — в `Styles/system_prompts.json`. Пресет может `extends` другой (наследование: потомок
  объединяет `system_prompt` + `system_prompt_suffix` и объединяет `style_tags_*`, глубина ≤ 3).
- **Ортогональные переключатели Writer.** `generate_face_prompts` (выдаёт `face_positive` /
  `face_negative` для FaceDetailer и вставляет блок инструкции по лицу в системный промпт), `nsfw`
  (по умолчанию безопасный контент), `prompt_format` (`natural` / `tags` / `weighted` / `structured`
  / `midjourney` / `booru`) и `blend_styles` (до 3 id/меток стилей через запятую, добавляются
  аддитивно). Они применяются при сборке в `styles.build_system_prompt`, никогда не хранятся
  внутри пресета. `prompt_mode` (`auto` / `standard` / `no_negative`) — единственный управляющий
  негативным промптом.

### Удалено
- **Избыточный переключатель `negative_prompt` узла Writer.** Негативный промпт теперь
  управляется только `prompt_mode` (`auto` = no-negative для дистиллированного семейства / Flux /
  SD3, `standard` = всегда, `no_negative` = никогда). Старый BOOLEAN `negative_prompt` был
  AND-перекрытием без отдельного поведения и удалён.
- **Избыточный переключатель `face_prompt` узла Writer.** `face_on` объединял
  `generate_face_prompts` ИЛИ `face_prompt` без отдельного кода, поэтому второй переключатель
  делал ровно то же, что `generate_face_prompts`. BOOLEAN `face_prompt` удалён;
  `generate_face_prompts` теперь единственный управляющий лицом (выдаёт `face_positive` /
  `face_negative` и вставляет блок инструкции по лицу).

- **Редактируемая копия стилей (вариант B).** При первом запуске вся папка `Styles/` копируется в
  `llm_prompt_studio_styles/` в каталоге вывода ComfyUI (не перезаписывается). Кнопки
  **Reload Styles** / **Reset Styles** перечитывают с диска / восстанавливают поставляемый набор.
- **Кнопки Reload Styles / Reset Styles (вместо старых переключателей).** Два `BOOLEAN`-переключателя
  узла (`reload_presets`, `reset_styles`) удалены — их поведение перенесено в кнопки узла **Reload Styles**
  (перечитывает `Styles/` с диска и обновляет комбо `style_preset`) и **Reset Styles** (удаляет
  пользовательскую копию, возвращает поставляемый `Styles/`). Кнопки теперь подключены к системе
  `Styles/` (раньше ошибочно указывали на устаревший `presets_default.json`), поэтому реально обновляют
  выпадающий список стилей.
- **Расширены стили Cinema.** `Styles/cinema.json` вырос с 3 до 34 пресетов: 19 стилей режиссёров
  (Кубрик, Нолан, Тарантино, Финчер, Скотт, Вильнёв, дель Торо, Бёртон, Вонг Кар-вай, Куросава,
  Тарковский, Коппола, Малик, Пон Джун-хо, братья Коэн, Пол Томас Андерсон, Годар, Эйзенштейн,
  Фриц Ланг) и 12 жанровых (Нуар, Нео-нуар, Спагетти-вестерн, Вестерн, Слешер, Found Footage,
  Зомби / Постапокалипсис, Документалистика, Мокьюментари, Мюзикл, Грайндхаус, Артхаус). Каждый
  новый пресет несёт и `system_prompt_no_negative` с фокусом стиля (режим no-negative сохраняет
  стиль, устраняя пробел в старых коротких записях «Style focus:»).
- **Исправлен дублирующийся стиль `Gothic Horror`.** В `Styles/fantasy_horror.json` два пресета
  имели одинаковое имя «Gothic Horror» (`gothic_horror` и `gothic_architecture_horror`). Второй
  переименован в **Gothic Ruins** (хоррор руин/соборов), чтобы в комбо не было дубликата.
- **Face Detailer: режим детекции `yolo_bbox_seg`.** Новый вариант `detection_method`:
  лицо ищет уверенная bbox-модель (`yolo_model_name`) с обычным `detection_threshold`, а
  сег-модель (`yolo_seg_model_name`) используется только для формы маски внутри этого
  кропа (сопоставление по IoU). Надёжная детекция (не нужно опускать `detection_threshold`
  до ~0.1) плюс рефайн по реальному контуру лица — полезно для лиц вполоборота, где чистый
  `yolo_seg` промахивается или даёт ложные срабатывания. При отсутствии пересечения с
  сег-маской или если сег-модель не выбрана — используется прямоугольная/овальная маска.
- **Face Detailer: бикубический ресайз кропа.** Кроп лица теперь ресайзится бикубической
  интерполяцией (`tensor_resize`) вместо билинейной, сохраняя детали при обратном
  уменьшении после VAE-декода.
- **Face Detailer: отдельный `seg_threshold`.** Новый виджет `seg_threshold` (по умолчанию
  `0.1`) задаёт уверенность сег-модели независимо от `detection_threshold` (детекция bbox).
  В `yolo_seg` он управляет детекцией лица, в `yolo_bbox_seg` — только получением формы
  маски внутри найденного bbox-моделью прямоугольника. Убрано прежнее жёсткое значение
  `0.01`; теперь покрытие масками и ложные срабатывания регулируются отдельно по моделям.
- **Face Detailer: дополнительные YOLO-детекторы лиц.** Добавлены веса
  YOLOv10/11/12 (n/s/m) и YOLO26 для детекции лиц (`.pt`) в `models/ultralytics/bbox/`.
  Они автоматически подхватываются `project_local_ultralytics_bbox()` и появляются в
  выпадающем списке `yolo_model_name` без изменений кода. Все проверены локально
  (ultralytics 8.4.x): уверенно детектируют лица (класс `0`) с conf 0.78–0.95 на
  реальных фото, включая мелкие и слабо освещённые лица.
- **Документация: `Plans/Algorithms.md`.** Подробное описание алгоритмов работы всех 10
  нод (Writer, Image Critic, Scene Builder, Smart Loader, Smart Parameters, Smart
  Multi-Clip, KSampler Hires Fix, Face Detailer, Smart Save, Library Loader) и их
  опорных модулей (`lm_http`, `model_meta`, `parsing`, `model_recommendations`,
  `_distilled_presets`, `presets`, `vram`, `_ksample`, `_latent_upscaler`, `_imgutils`,
  `_contracts`): потоки данных, решения по no-negative режиму, загрузке/профилированию
  LLM, детекции семейства/архитектуры, field-retry, гендерному/классовому фильтрам
  Face Detailer и координации VRAM.
- **Face Detailer: фильтр класса для `yolo_seg` (теперь комбобокс).** Виджет
  `yolo_seg_class` — комбобокс, который **автоматически заполняется из выбранной
  `yolo_seg_model_name`**: при выборе сег-модели в списке появляются реальные имена её
  классов (напр. `face`, `hair`, `skin`) вместо «сырого» индекса. Детекции других классов
  (person, автомобиль и т.п.) игнорируются, что убирает ложные срабатывания `yolo_seg` —
  порог `detection_threshold` можно держать нормальным (~0.5) вместо опускания до 0.1–0.2.
- **Face Detailer: выравнивание яркости после инпейнта.** Отрефайненное лицо
  теперь согласуется по яркости/контрасту с окружением в пределах растушёванной
  маски (`match_luminance`), устраняя шов «лицо ярче остального кадра».
- **Face Detailer: фильтр пола (gender).** Новый виджет `gender_filter`
  (`any` / `female` / `male`, по умолчанию `any`) ограничивает рефайн одним полом.
  Лёгкая ultralytics-модель классификации пола (выбирается в `gender_model_name`,
  помещается в `models/ultralytics/gender/`) запускается на каждом кропе лица; лица,
  чей предсказанный класс не совпадает с `gender_filter`, пропускаются. Номер
  «женского» класса теперь выбирается **комбобоксом** `gender_model_female_class`, который
  автоматически заполняется из выбранной `gender_model_name` (реальные имена классов,
  напр. `female`, `male`) вместо «сырого» индекса; если модель не выбрана, фильтр логирует
  предупреждение и обрабатывает все лица. Детекция пола работает при **любом** методе
  детекции (haar, bbox, seg, yolo_bbox_seg), а выравнивание яркости отрефайненного лица
   (`match_luminance`) применяется на маске каждого метода.
- **Face Detailer: `match_color` при композитинге инпейнта.** Новый виджет
  `match_color` (`luminance` / `lab` / `histogram` / `none`, по умолчанию `luminance`)
  задаёт, как отрефайненное лицо вливается обратно в кадр. `luminance` (прежнее
  всегда-включённое поведение) выравнивает только яркость/контраст; `lab` делает то же
  аффинное преобразование в цветовом пространстве LAB, убирая и цветовые швы; `histogram`
  — поканальное CDF-согласование с окружающим оригиналом; `none` — без выравнивания.
  OpenCV импортируется лениво, так что узел грузится и без него (фоллбэк на `luminance`).
- **Critic и Writer: CV-подсказка о сцене.** Новый переключатель `cv_scene_hint`
  (по умолчанию вкл) запускает дёшево анализ на OpenCV (тип сцены, освещённость, число
  лиц — без дополнительного vision-вызова) и подаёт его LLM как контекст. Critic
  подставляет его в промпт оценки (и показывает в выходе узла `scene_hint`); Writer
  принимает опциональный вход `image` и добавляет подсказку в бриф, чтобы генерируемый
  промпт соответствовал содержимому (аниме/иллюстрация против фото, натуральные тона
  кожи для портретов). Классификации нужны только OpenCV/numpy (без scikit-learn/skimage).
- **Face Detailer: порог уверенности пола (`gender_threshold`).** Новый виджет FLOAT
  (по умолчанию `0.5`) задаёт минимальную уверенность классификатора пола. Лица, чья
  предсказанная уверенность пола ниже порога, считаются `unknown` и **сохраняются** (не
  отбрасываются гендер-фильтром) независимо от `gender_filter`. Работает только при
  `gender_filter != any`.

### Изменено
- **Face Detailer: `detection_threshold`** снабжён поясняющей подсказкой и
  рекомендуется держать около 0.5 после включения фильтра по классу.
- **Face Detailer: логирование в консоль ComfyUI (английский + диагностика).**
  Все строки `[FaceDetailer]` теперь на английском. Детекция пишет причину
  отбрасывания лиц: bbox — `dropped N below confidence threshold`; seg — ещё и
  раздельно `wrong class != <yolo_seg_class>` против `below confidence threshold`.
  Шаг пола логирует итог по **определённому полу и их количеству** (`N female,
  M male, K unknown`), а при активном `gender_filter` — ещё и каждое отброшенное
  лицо (`predicted class X (female/male), wanted <gender>`) с общим счётчиком
  отброшенных. При запуске и для каждого кадра/лица по-прежнему пишется: старт
  (метод, guide_size, max_size, drop_size, yolo_seg_class), обнаруженное лицо
  (размер в px), коэффициент увеличения до guide_size, ограничение кропа по
  max_size, пропуск лица (уже >= guide_size, мельче drop_size) и итог (сколько
  лиц обработано).
- **Face Detailer: виджет `drop_size`.** Лица, короткая сторона которых меньше
  заданного размера (px), пропускаются и не обрабатываются (по умолчанию `0` —
  не отсекать никакие лица).
- **Writer: стиль не лепит фотографические теги в неподходящих случаях (Q4).**
  Из общих «Engineering rules» всех пресетов убран слой `camera/lens` — он
  заставлял модель добавлять «85 mm lens» и подобное в аниме/иллюстрацию/живопись.
  Фотографические пресеты по-прежнему описывают камеру/объектив в собственном
  тексте, поэтому для них поведение не меняется.
- **Writer: выбранный стиль влияет и на `face_positive`/`face_negative` (Q4).**
  Стилевые теги пресета теперь добавляются и в промпты лица, так что отрефайненное
  Face Detailer-ом лицо соответствует выбранному стилю.
- **Writer: `generate_face_prompts = off` больше не генерирует face-промпты (Q5).**
  Поля `face_positive`/`face_negative` принудительно обнуляются, даже если модель
  вернула их в JSON, — FaceDetailer корректно падает на основные промпты.
- **Writer / Scene Builder: стандартизация `scene_name` (Q6).** Любое непустое
  имя сцены от модели (кавычки, «Scene: …», смешанный регистр, markdown) теперь
  приводится к единообразному lowercase slug через `slugify`; пустое значение
  по-прежнему заменяется на `slugify(positive)`.
- **Writer: формат `structured` усилен для маленьких локальных моделей.**
  Фрагмент `prompt_format.structured` в `Styles/system_prompts.json` теперь показывает
  конкретный пример блочной разметки и явно запрещает переиспользовать содержимое
  примера, поэтому компактные модели (напр. qwen3-4b на CPU) выдают буквальные
  заголовки `[Subject]` / `[Lighting]` / `[Style]` / `[Camera]` / `[Composition]`,
  не копируя пример в ответ.
- **Writer: `blend_styles` теперь строго сплавляет все указанные стили.**
  `styles.build_system_prompt` объединяет `blend_note` каждого стиля (при пустом или
  совпадающем с именем — берётся первая строка `system_prompt`, усечённая до ≤200
  символов) в строгий заголовок «fuse ALL … every listed style MUST be clearly and
  visibly present … never drop any». Пресеты `oil_painting` и `cyberpunk` получили
  содержательные `blend_note`, чтобы оба стиля появлялись в сплавленном промпте.

### Исправлено
- **Дублирование стилевых тегов (Audit7/1.2).** `apply_preset_style` теперь
  исключает повторы позитивных (и face-позитивных) стилевых тегов относительно уже
  имеющихся в промпте — ранее теги могли добавляться по нескольку раз.
- **Падение повтора полей при сетевой ошибке (Audit7/1.3).** Цикл повтора пропущенных
  полей в writer теперь оборачивает каждый вызов `chat_completion` в `try/except`:
  транзитная ошибка транспорта считается попыткой и повторяется до `max_field_retries`,
  вместо аварийного завершения узла.
- **YOLO переинициализировалась для каждого кадра (Audit7/2.1).** Экземпляр ultralytics
  `YOLO` теперь кэшируется по пути модели (`_get_yolo_model`) и переиспользуется для
  всех кадров батча (и между запусками), вместо пересоздания при каждой детекции.
- **SSRF-фильтр отвергал локальные имена хостов (Audit7/3).** `validate_server_url`
  теперь резолвит не-IP хост через `socket.getaddrinfo` и принимает его, только если
  *все* полученные адреса — loopback/private/link-local. Локальные имена вида `nas.home`
  теперь работают без отключения защиты (`ALLOW_PUBLIC_SERVER_URLS`).
- **Утечка внутренних деталей ошибок через API (Audit7/4.1).** `server_routes.py`
  больше не возвращает клиенту сырые строки исключений — маршруты логируют реальную
  ошибку и возвращают общее сообщение.

### Исправлено (Audit4)
- **Детекция семейства чекпоинта игнорировала родительскую папку (`#1.1`).**
  `detect_checkpoint_family_info` сканировал только имя файла + метаданные safetensors,
  поэтому файл с обычным именем внутри папки `Lightning/` (и т.п.) ошибочно определялся
  как `base`. Теперь и `detect_checkpoint_family`, и `detect_checkpoint_family_info`
  сканируют также имя родительской папки (через общий хелпер `_scan_checkpoint_text`);
  `detect_checkpoint_family_info` возвращает `source: <filename | metadata | base | override>`.
- **`vision_check` в Scene Builder блокировал стадию 2 (`#1.2`).** Проверка зрения
  выполнялась до разбора стадии, поэтому не-vision модель не могла запустить compose
  (стадия 2). Проверка теперь ограничена стадией 1 (`_has_image` / `_stage_is_describe`),
  так что стадия 2 компонует из сохранённого описания без vision-модели.
- **Инструкция face-промпта в Writer стиралась оверрайдом пресета (`#2.1`).** Инструкция
  добавлялась в системный промпт, а затем перезаписывалась `system_prompt` пресета. Теперь
  она добавляется **после** оверрайда пресета, поэтому face-промпты генерируются даже при
  выбранном стилевом пресете.
- **Smart Loader отбрасывал CLIP-сторону LoRA (`#2.2`).** `load_lora_for_models`
  вызывался с `strength_model, 0`, оставляя веса CLIP нетронутыми. Теперь используется
  `strength_model` и для модели, и для CLIP, так что CLIP-зависимая LoRA (например, стилевая)
  реально влияет на текстовый энкодер.
- **Профиль `auto` для моделей ≥7B возвращал неверный профиль (`#2.3`).** `recommend_for`
  возвращал `baseline` для ≥7B, что противоречило его docstring (near-greedy `structured`).
  Теперь возвращается `{"profile": "structured", "structured": True}` (t≈0.1 + JSON-схема),
  что даёт моделям максимальную точность разбора схемы. Золотые тесты обновлены.
- **Падение Smart Save на EXIF вне try/except (`#2.4`).** `img.save(..., exif=exif.tobytes())`
  выполнялся вне защищённого блока, поэтому некорректный EXIF ломал всё сохранение. Сериализация
  EXIF и сохранение теперь обёрнуты в try/except с фолбэком на сохранение без метаданных; сбои
  логируются, а не прерывают работу.
- **`_pixel_stage` в KSampler Hires Fix падал без VAE (`#2.5`).** Pixel-путь апскейла
  разыменовывал `optional_vae` без проверки; при отсутствии VAE возникал `AttributeError`.
  Теперь выдаётся понятный `RuntimeError` с указанием подключить `optional_vae`.
 - **Тесты:** добавлен `test_detect_family_info_from_parent_folder` (детекция по папке),
   удалён дубликат `test_detect_family_from_parent_folder`, убран no-op `assert True` в
   `tests/test_vram.py`.

### Changed
- **Убран переключатель `negative_prompt` у Writer.** `BOOLEAN`-вход `negative_prompt` был
  избыточен: `prompt_mode` уже управлял негативным промптом (`auto` / `standard` / `no_negative`).
  Переключатель удалён из `INPUT_TYPES`, `execute` и `_run`; теперь `prompt_mode` — единственный

  отрицательные).** `detect_checkpoint_family` требовал разделителя после токена семейства, поэтому
  слитые CamelCase-имена вроде `HyperSDXL`, `SDXLLightning`, `TurboSDXL` и `LCMXL` (и вариант LoRA
  `dmd2`) сообщались как `base`, так что режим `no_negative` никогда для них не включался
  автоматически. Определение теперь чувствительно к регистру: слово семейства принимается как
  самостоятельный токен или CamelCase/версионное продолжение (`HyperSDXL`, `LCMXL`, `dmd2`), всё ещё
  отвергая маркеры, склеенные в более длинное строчное слово (`hypernetwork`, `calcium`,
  `flash_attention`). Версионированные варианты (`dmd2`) сопоставляются с семейством `dmd`.
- **Определение семейства чекпоинта давало ложные положительные из свободного текста метаданных.**
  Сканировался весь JSON метаданных safetensors (включая `description`/`comments`), поэтому базовая
  модель, чьё описание говорило «hyper-realistic» / «lightning-fast» / «turbo-charged», ложно
  помечалась как дистиллированная. Сканирование теперь использует только структурированные поля
  метаданных и исключает ключи свободного текста, поэтому описания больше не могут вызвать ложное
  совпадение семейства (структурированные поля вроде `modelspec.title` всё ещё учитываются).
- **Писатель тратил токены, выдавая поля лица, когда они не запрашивались.** Базовые промпты
  `writer_system` / `writer_system_no_negative` предписывали `face_positive` / `face_negative` в
  каждом ответе и показывали их в JSON-примере, поэтому модель возвращала их даже при выключенном
  `generate_face_prompts`. Промпты теперь помечают поля лица как ОПЦИОНАЛЬНЫЕ — включены только когда
  запрошена генерация промптов лица, иначе опущены (`parse_prompt_json` уже по умолчанию даёт
  пустые строки для отсутствующих полей лица, а узел откатывается к основным промптам).

  было подключить далее по цепочке (не только через кнопку «Send to Writer»).
- **Структурированное логирование**: все модули используют Python `logging` под логгером
  `llm_prompt_studio` с префиксом `[LLMPromptStudio]` (заменяет `print()`), включая тайминги вызовов
  LLM и ошибки.
- **Усиление безопасности**:
  - `validate_server_url()` — защита от SSRF. Только `http`/`https` и, по умолчанию, локальные/частные
    хосты (`localhost`, loopback, RFC-1918, link-local). Установите `ALLOW_PUBLIC_SERVER_URLS = True`
    в `lm_http.py`, чтобы разрешить удалённые хосты.
  - `safe_path_in_output()` — защита от обхода путей. Пути библиотеки и сохранения ограничены
    директорией вывода ComfyUI. Установите `RESTRICT_PATHS_TO_OUTPUT = False` в `library.py`, чтобы
    разрешить пути вне неё.
  - Атомарные записи библиотеки промптов (`.tmp` + `os.replace`) для предотвращения повреждения при
    параллельных записях.
- **Ограниченные кэши**: `_prompt_cache` (макс 128), `_model_cache` (макс 32) и JS-карта `lastSaveData`
  (макс 100) теперь вытесняют старейшие записи вместо бесконечного роста.
- **Набор тестов**: `tests/` с золотыми тестами pytest для парсинга промптов/критика JSON, логики
  спасения, `slugify` и определения семейства чекпоинтов (`python -m pytest tests/ -v`).
- **`.gitignore`** (кэши Python, venv, файлы ОС/IDE, логи).
